# M1：自习座位预约接口 v1

本版固定编号、函数名和公开格式，不设计内部结构。依据：[任务书](../../../../Pj-任务书.pdf)第 5—6 页及第 1—2 页；初稿来源 PR #2。**本地 v1 初稿，未实现、未完成人工验收。** 本版采用集成示例和统一配置入口；首版业务边界见开发指导第4节，不代表成员已经评审。

调用、身份、错误、时间、分页与请求版本统一引用[公共规则 v1](../../../开发指导.md#3-公共规则-v1)。函数均为 fn(input)，输出指成功的 data；类型记号同 [D](../Module_D/D.md)。列表返回公共分页，不另列对象定义。

## 1. 功能范围

| 编号 | 必须完成的功能 |
| --- | --- |
| M1-F01 | 系统配置、角色和权限管理，最大单次预约时长默认4小时且可调 |
| M1-F02 | 教室座位登记、注销、基础可用性、开放时间；院系限制、唯一座位号、固定或导轨插座标记 |
| M1-F03 | 条件搜索与目标时段可预约性 |
| M1-F04 | 整点小时预约、时长限制、同座位无重叠占用 |
| M1-F05 | 教室每日动态编码或二维码、学生签到，Web或微信选择一种 |
| M1-F06 | 前15分钟提醒、后10分钟未签到提醒、后15分钟取消释放提醒并记一次违约 |
| M1-F07 | 本人历史与同座位新时段再次预约 |
| M1-F08 | 授权运营查询与统计 |
| M1-F09 | 状态来源追踪；采用集成示例时接收M2占用与M3维修限制及各自解除 |

来源追踪是明确要求，集成链路采用任务书示例。当前不加入主动取消个人预约、封禁、导出。以下前端操作为 USER；后台任务不开放前端触发接口。

## 2. 前端与屏幕接口

| 服务／函数／调用方 | 输入格式 | 输出格式 |
| --- | --- | --- |
| M1-S03 搜索 search_seats(input)／学生 | {spaceId?:str,socketTag?:FIXED/RAIL,startTime?:time,endTime?:time,limit?:int,cursor?:str} | 分页单项 {space:同D-S06 GET_SPACE,seat:同D-S06 GET_SEAT,available:bool/null,reason:str} |
| M1-S04 预约 reserve_seat(input)／学生 | {seatId:str,startTime:time,endTime:time,requestId:str} | {reservationId:str,userId:str,spaceId:str,seatId:str,startTime:time,endTime:time,status:RESERVED/CHECKED_IN/CANCELLED_NO_SHOW/CANCELLED_MAINTENANCE/ENDED,checkInTime:time/null,version:int} |
| M1-S05 凭据 get_check_in_code(input)／授权屏幕或管理用户 | {spaceId:str} | {spaceId:str,date:str,token:str,expiresAt:time} |
| M1-S06 签到 check_in(input)／学生 | {reservationId:str,token:str,expectedVersion:int,requestId:str} | 同 S04 输出，成功签到为 CHECKED_IN，checkInTime 非空 |
| M1-S07 本人列表 get_my_reservations(input)／学生 | {status?:同S04状态,startTime?:time,endTime?:time,limit?:int,cursor?:str} | 分页，单项同 S04 输出 |
| M1-S07 本人详情 get_my_reservation(input)／学生 | {reservationId:str} | 同 S04 输出 |
| M1-S08 运营 get_usage(input)／授权运营用户 | {startTime:time,endTime:time,spaceId?:str,seatId?:str,limit?:int,cursor?:str} | {startTime:time,endTime:time,checkedAt:time,reservations:同S07分页,reservationCount:int,checkedInCount:int,limits:[见本节说明]} |

S03、S07 的开始结束时间必须同时提供或同时省略。未选时段时 S03.available=null；选时段再判断冲突。预约人从凭据取得，提交时重查院系、开放、整点、时长和占用；再次预约复用 S04。搜索排除越权、注销、基础不可用、维修下架座位。

S07日期范围按预约开始时间筛选；必须早于结束时间。具体参数错误、权限拒绝与状态冲突按开发指导公共错误规则，不由各模块另选状态码。

S05.date 为校园日期 YYYY-MM-DD；普通学生不能调用 S05。签到限本人、对应教室、有效凭据；签到窗口为[开始时间,开始后15分钟)。重复请求不重复签到，成功签到不能被同次未签到检查取消；旧版本冲突须重查记录。

S08.limits 单项格式：{source:M1/M2/M3,businessId:str,spaceId:str,seatId:str/null,startTime:time/null,endTime:time/null,state:ACTIVE,sourceVersion:int/null}。个人预约有 seatId，外部整室限制为 null；维修无时段。统计按预约开始时间，已签到按 checkInTime 非空计；总数不随分页改变。限制只列查询时有效且影响所选时段的记录，不计算历史维修时长，本版按此口径实现。

### 管理入口

| 服务／函数 | 输入格式 | 输出格式 |
| --- | --- | --- |
| M1-S01 get_config(input) | {owner:M1/M2/M3/D} | {owner:M1/M2/M3/D,config:对应模块查询输出} |
| M1-S01 update_config(input) | {owner:M1/M2/M3/D,config:下表更新字段,expectedVersion:int,requestId:str} | 与 get_config 一致，config 是修改后完整查询格式 |
| M1-S02 manage_roles(input) | 与 D-S05 一致 | 与 D-S05 一致 |
| M1-S02 query_master(input) | 与 D-S06 一致 | 与 D-S06 一致 |
| M1-S02 maintain_master(input) | 与 D-S07 一致 | 与 D-S07 一致 |
| M1-S02 get_opening_times(input) | {spaceId:str} | {spaceId:str,timeRanges:[{startTime:time,endTime:time}],version:int} |
| M1-S02 set_opening_times(input) | {spaceId:str,timeRanges:[{startTime:time,endTime:time}],expectedVersion:int,requestId:str} | 与 get_opening_times 一致 |

| owner | config 更新字段／查询输出 |
| --- | --- |
| M1 | 更新 {maxReservationHours:int}；查询增加 {version:int}，初始为4小时、version=1 |
| M2 | 更新使用 M2-S08 update_approval_config 的业务设置；查询使用 get_approval_config 输出 |
| M3 | 更新使用 M3-S12 update_timeout_config 的业务设置；查询使用 get_timeout_config 输出 |
| D | 更新 {authMethod:PASSWORD,notificationChannel:EMAIL,notificationRetryLimit:int}；查询使用 D-S12 输出 |

config 更新字段不含 owner、operation、expectedVersion、requestId 或只读 version；M1 转调时补提供方要求的参数。设置由所属模块保存。开放区间不得重叠；空数组表示关闭，尚未配置时查询返回空数组、version=1。更改基础可用或开放规则不清除其他来源限制；基础停用、注销、院系与开放规则变更若破坏既有未终结预约，M1管理入口拒绝，并在校验与D维护期间阻止新的相关预约。

F06 后台仅处理仍未签到的预约，重复检查只记一次违约；取消保留 CANCELLED_NO_SHOW，不随时间变成 ENDED。维修下架时未终结个人预约转CANCELLED_MAINTENANCE，保留签到时间、不记违约，使用D的M1_MAINTENANCE_CANCELLED通知；已终结记录不改。通知或审计失败保留可追踪结果，不删除业务记录。

## 3. 跨模块接口

### M1-S09 get_room_availability(input)／M2

- 输入：{spaceId:str,startTime:time,endTime:time}。
- 输出：{spaceId:str,startTime:time,endTime:time,canOccupy:bool,blockedBy:[BASE/OPENING/M1/M2/M3/NO_SEATS],reasons:[str],checkedAt:time}。
- 判断整室能否整体占用，不返回人员信息；可用时两个原因数组均空，不可用时顺序对应、代码不重复。BASE 是主数据不可用，OPENING 是未开放；其余为对应来源限制或无座位。查询不预留教室，实际占用重查。

### M1-S10 change_room_limit(input)／M2、M3

- 输入：{source:M2/M3,businessId:str,spaceId:str,action:OCCUPY/REPAIR/RELEASE,businessState:下表值,startTime:time/null,endTime:time/null,sourceVersion:int,requestId:str}。
- 成功输出：与 S11 相同，queriedRequestId 为本次 requestId、requestStatus=SUCCESS；明确拒绝按公共规则返回错误，不能确认完成用 UNAVAILABLE，调用方通过 S11 核实。

| source／action | businessState | 时段／含义 |
| --- | --- | --- |
| M2／OCCUPY | APPROVED | 两个时间必填，最终通过后占用全部座位，整体成功或拒绝 |
| M2／RELEASE | REJECTED、TIMEOUT_CANCELLED；CANCELLED 仅F05采纳后 | 同一申请时段，只解除本申请 |
| M3／REPAIR | REPAIRING | 两个时间均为null，使该室停止接受新预约，并终结该室未终结个人预约为CANCELLED_MAINTENANCE |
| M3／RELEASE | ACCEPTED | 两个时间均为null，只解除本工单 |

来源匹配可信模块；同业务引用固定教室与时段，不能重试时换目标。同编号不重复执行，旧版本不覆盖新版本；无原限制的解除仍保留终结版本，防迟到占用或下架重新生效。解除本业务不代表整室可用。

成功RELEASE返回currentLimit.state=RELEASED及该解除版本，即使此前未占用或下架；同一来源版本重复相同业务内容不重复生效，换内容拒绝。

合法新版本因占用冲突被拒绝时保留该请求结果REJECTED，最高已处理版本不表示一定生成限制；旧版本拒绝不推进最高版本。身份或参数检查未通过不形成业务处理记录。

### M1-S11 get_room_limit(input)／原来源模块

- 输入：{source:M2/M3,businessId:str,requestId?:str}。
- 输出：{source:M2/M3,businessId:str,spaceId:str/null,maxProcessedVersion:int/null,currentLimit:{source:M2/M3,businessId:str,spaceId:str,startTime:time/null,endTime:time/null,state:ACTIVE/RELEASED,sourceVersion:int}/null,queriedRequestId:str/null,requestStatus:SUCCESS/REJECTED/UNKNOWN/null,message:str}。
- 指定编号核实原请求，不指定则 requestStatus 与 queriedRequestId 均为 null。没有记录时空间、最高版本、当前限制为 null；指定请求结果 UNKNOWN，不表示请求永远不会执行。
- 原请求结果、当前限制、最高已处理版本分别说明，不能用较高版本或旧成功回执证明当前仍占用。

## 4. 外部调用与权限

| 服务 | 固定用法 |
| --- | --- |
| D-S02、S04 | 当前身份和权限；引用D的凭据、permissionCode、targetScope格式 |
| D-S05、S06、S07 | 管理入口与主数据；原样引用D格式，不给前端模块凭据 |
| D-S09、S10、S11 | 提醒与投递核实、审计；来源M1，通知kind使用D的M1目录 |
| M2-S08、M3-S12、D-S12 | 读取与更新配置，引用各提供方格式 |

权限编码：S03用 m1.seat.read；S04用 m1.reservation.create；S06用 m1.reservation.check_in；S07用 m1.reservation.read；S08用 m1.usage.read；开放时间用 m1.opening.read / m1.opening.manage；S01用全局 m1.config.read / m1.config.manage 并核验提供方配置权限。S05屏幕使用D签发的专用账号USER凭据，授予 m1.check_in_code.read且只限该SPACE；管理用户同样核验对应空间权限。管理代理复用D对应权限；本人关系、院系限制继续由M1检查。S09—S11只允许授权模块，不开放学生直调。

本版学生端为Web，提前范围、同人重叠、签到、管理变更、维修取消、统计与补偿按开发指导第4节；后续修改同步接口与测试。仍须实际实现与人工验收，不能各自增加主动取消、封禁或导出。
