# M2：整教室预约与审批接口 v1

本版固定公开函数和格式，不设计内部结构。依据：[任务书](../../../../Pj-任务书.pdf)第1—2页，初稿来源PR #4；当前不要求固定第二人复核。**公开接口已实现并有本模块测试；真实 HTTP 联调与人工验收未完成**（见第6节）。

引用[公共规则 v1](../../../开发指导.md#3-公共规则-v1)，函数均接收 input，输出是成功的 data，类型记号同[D](../Module_D/D.md)。D负责身份与主数据，M1负责真正占用；不直接读其他模块业务数据。

## 1. 功能范围

| 编号 | 原要求 |
| --- | --- |
| M2-F01 | 权限、空间范围与业务关系门槛 |
| M2-F02 | 提交申请，唯一编号与待审批状态 |
| M2-F03 | 多级通过或驳回；本版按逐级至少两级、每级一人给出格式 |
| M2-F04 | 待审批超时自动撤销 |

初稿补充功能已纳入本轮必做：M2-F05主动撤销待审批申请；M2-F06统一查询；M2-F07专用配置页面，复用S08已有配置字段；M2-F08维修影响提示。表单仍按本版固定输入实现，不增加会签、加签、修改重提、改期、统计或导出。

## 2. 基本接口

| 服务／函数／调用方 | 输入格式 | 输出格式 |
| --- | --- | --- |
| M2-S01 get_allowed_actions(input)／用户 | {spaceId?:str} | {actions:[{operation:SUBMIT/APPROVE/READ/CONFIGURE/CANCEL/MANAGED_READ,allowed:bool,allowedScopes:同D-S04,reason:str}]}，各操作按当前权限返回 |
| M2-S10 get_classroom_options(input)／申请人 | {departmentId?:str,startTime?:time,endTime?:time,limit?:int,cursor?:str} | 分页单项 {space:同D-S06 GET_SPACE,availability:同M1-S09输出/null} |
| M2-S02 submit_application(input)／申请人 | {spaceId:str,startTime:time,endTime:time,purpose:str,requestId:str} | {application:下述格式,approvals:[],seatSync:null,notifications:同S05通知格式} |
| M2-S03 get_approval_tasks(input)／当前审批人 | {applicationId?:str,spaceId?:str,limit?:int,cursor?:str} | 分页，单项同S05；只含本人当前可审批申请，指定编号仍返回分页 |
| M2-S04 submit_approval(input)／当前审批人 | {applicationId:str,level:int,decision:APPROVE/REJECT,comment?:str,expectedVersion:int,requestId:str} | 同S05，含本次决定；comment 省略为空 |
| M2-S05 get_application(input)／申请人或处理过本申请的审批人 | {applicationId:str} | 见本节格式 |

S02.application 的格式：{applicationId:str,applicantId:str,spaceId:str,startTime:time,endTime:time,purpose:str,status:PENDING/APPROVED/REJECTED/TIMEOUT_CANCELLED/CANCELLED,currentLevel:int/null,version:int,configVersion:int,submittedAt:time,currentLevelStartedAt:time,expiresAt:time,terminatedAt:time/null,terminationReason:str}。S02成功为PENDING、首级；审批终结后currentLevel=null。CANCELLED用于F05主动撤销。

S05输出：
- {application:同S02的application,approvals:[{approvalId:str,applicationId:str,level:int,approverId:str,decision:APPROVE/REJECT,comment:str,decidedAt:time,applicationVersion:int}],seatSync:下述格式/null,notifications:下述格式}。
- seatSync：{requestId:str,sourceVersion:int,status:PENDING/SUCCESS/REJECTED/UNKNOWN,result:同M1-S11输出/null,checkedAt:time/null,message:str}，未发出过限制操作为null。
- notifications：[{requestId:str,status:PENDING/ACCEPTED/REJECTED/UNKNOWN,notification:同D-S09输出/null,message:str}]。ACCEPTED只表示受理；实际投递看notification.deliveries，信息按当前身份可见范围返回。

S10的时间同时提供或省略，未传时availability=null。选项与查询不预留教室。S02校验权限、时段、用途和配置；本版冲突时拒绝，不自动套用个人预约4小时上限。

提交或中间级通过不占用，最后一级通过才发占用。APPROVED表示审批通过；seatSync确认占用成功才显示预约成功。若旧请求曾成功但currentLimit已解除，不宣称当前仍占用。

越权、非当前审批人、越级、过期、已终结、旧版本或矛盾决定拒绝。重复原请求不重复产生决定；审批与超时只能一个变更生效。后台按配置周期终结到期PENDING申请，递增版本并解除本申请，通知与审计失败不抹掉业务状态；不开放前端超时接口。

每次有效状态变更后version递增，审批记录的applicationVersion是决定后的版本；历史记录不覆盖。没有通知为[]，尚未提交D为PENDING，D确认受理为ACCEPTED，原发送明确拒绝为REJECTED，无法确认受理为UNKNOWN。

## 3. M1 配置入口

### M2-S08 get_approval_config(input)、update_approval_config(input)／M1 USER

F07专用页面允许M2管理前端USER调用，权限与版本规则相同。

- 查询输入：{}。
- 查询输出：{version:int,applicationScopes:[同D-S04的targetScope],approvalLevels:[{level:int,approverId:str}],clockStart:SUBMISSION/CURRENT_LEVEL/null,timeoutSeconds:int/null,checkIntervalSeconds:int/null}。
- 更新输入：{applicationScopes:[同上],approvalLevels:[同上],clockStart:SUBMISSION/CURRENT_LEVEL,timeoutSeconds:int,checkIntervalSeconds:int,expectedVersion:int,requestId:str}。
- 更新输出：与查询一致，新version递增。M1-S01.config直接使用本接口业务设置，不含expectedVersion、requestId或只读version。

门槛由固定业务权限加applicationScopes共同判断，申请须落在至少一个配置范围；审批另查当前级人选。初始空配置version=1、两个数组为空、时钟与两个时限为null，表示未配置，不能提交申请。更新要求范围非空、至少两级从1连续排列、每级一名合格审批人、时间参数为正整数。

SUBMISSION从提交计时，换级不重置；CURRENT_LEVEL从每级进入计时。新申请用新配置，在途保留原依据。实际开发与测试人选、数值按开发指导和共同测试初始化；空库未seed时仍是未配置，不能自行放行。基本规则维护不依赖F07专用页面；表单扩展未纳入本版格式。

## 5. 跨模块调用与权限

| 提供方／函数 | 固定请求与返回 |
| --- | --- |
| D-S02 get_identity、D-S04 check_permission | 身份与权限，目标采用SPACE及申请spaceId；格式引用D |
| D-S06 query_master | LIST_SPACES/GET_SPACE；原样使用D的主数据字段 |
| D-S08 query_people | purpose=APPROVAL、permissionCodes=[m2.approval.approve]，targetScope为配置范围或申请SPACE；核验人选用BY_IDS及userIds，返回引用D |
| D-S09 send_notification、D-S10 get_notification、D-S11 audit | 来源M2、businessId=applicationId；通知kind使用D的M2目录，返回原样引用 |
| M1-S09 get_room_availability | {spaceId,startTime,endTime}，返回原样引用M1 |
| M1-S10 change_room_limit | {source:M2,businessId:applicationId,spaceId,startTime,endTime,sourceVersion:申请版本,requestId,action,businessState}，返回引用M1-S11 |
| M1-S11 get_room_limit | {source:M2,businessId:applicationId,requestId:原写回编号}，结果放入seatSync.result |

M1写回对应值：最终通过OCCUPY/APPROVED；驳回RELEASE/REJECTED；超时RELEASE/TIMEOUT_CANCELLED；主动撤销RELEASE/CANCELLED。每次状态变更用更高来源版本，不换目标或原请求内容。只解除本申请，旧占用不能覆盖新解除。

seatSync为SUCCESS仅指定请求确认成功；原写回4xx明确拒绝或S11.requestStatus=REJECTED时为REJECTED，写回超时、503、500或无法确认时UNKNOWN，未尝试PENDING。核实接口失败不能推断原请求被拒绝，也不抹掉已知成功；checkedAt只记录明确回执或成功核实时间。公共错误不伪造成成功data，收到成功查询后保存M1原返回，当前限制与原请求结果分别判断。

固定权限：提交与教室选项m2.application.submit；S03/S04 m2.approval.approve；S05及本人/已办查询m2.application.read；管理查询m2.application.read_all；主动撤销m2.application.cancel；S08 m2.config.read / m2.config.manage且全局范围。维修提示复用申请查看资格，所属关系和轮次由M2检查。调用D时还满足D的服务权限。

本版F05—F08均须实现；两级人选、时限、最小表单、时段和冲突处理按开发指导第4节。明确占用冲突保留审批通过及seatSync=REJECTED，不自动覆盖其他预约；未知结果按原编号补偿，不显示预约成功。模块自检、测试与真实验收仍须完成。

## 6. 实现补充说明（本轮）

本节只记录实现时对本文档未写死细节的补全，不改变上面已登记的编号、函数名和字段。

- **提交时可用性检查**：S02 在落库前调用 M1-S09；`canOccupy=false` 直接按 CONFLICT 拒绝，不生成申请。最终级通过仍由 M1-S10 原子复查，因此提交通过不等于占用成功。
- **未配置时的行为**：`applicationScopes` 或 `approvalLevels` 为空时 S02 拒绝提交（未配置不等于放行），与 S08 初始 `version=1` 的未配置状态一致。
- **申请范围的判定**：`GLOBAL` 覆盖全部空间；`DEPARTMENT` 按空间所属院系判定；`SPACE` 按空间标识判定。申请须落在至少一个配置范围内。
- **审批人资格**：S04 每次审批前用 D-S08 `BY_IDS` 重查该级审批人是否 ACTIVE 且 `eligible=true`；不合格按 CONFLICT 拒绝，不推进业务状态。
- **approved 状态的 seatSync**：最终级通过即状态 APPROVED，写回结果单独记在 seatSync；`REJECTED` 表示 M1 明确拒绝（如整室占用冲突），`UNKNOWN` 表示无法确认，由后台按原请求编号补偿并用 M1-S11 核实。
- **分页游标**：游标绑定当前筛选条件与 limit，筛选或 limit 变化须从第一页重查，否则按 INVALID_ARGUMENT 返回。
- **S08 调用方**：当前共同规则已允许M1管理入口USER转发和M2管理前端USER直连；两者都继续检查全局配置权限。本轮包含F07，不再把前端直连记为待确认冲突。
- **已实现范围**：`backend/m2/`（models、schemas、peers、business、service、api、main、seed、迁移 0002）、`frontend/m2/index.html`、`tests/m2/`。未做真实 HTTP 联调与容器部署（本机无 PostgreSQL/Docker）。

协调修复：人工提交、审批和撤销的审计保留实际userId，后台超时事件使用SYSTEM/M2；来源均为M2。配置审计使用稳定业务标识m2-approval-config，不再发送空标识。模块测试按D真实输入模型验证审计请求；原有REJECTED记录不自动改写或重发。
